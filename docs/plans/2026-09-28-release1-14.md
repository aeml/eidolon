## Feedback implementation checkpoint

- Actual report form now keeps drafts until a matching server save confirmation.
  Correlated `report_result` includes the saved queue reference; server emits it
  only after persistence. Existing legacy system chat/error is retained.
- Offline/disconnected sends, storage rejection, mismatched/late results and a
  15-second uncertain timeout preserve drafts. No automatic retry or duplicate
  click while pending. New session/form ownership removes old listeners/timers
  and prevents inheritance of another character's draft. No localStorage dump.
- Explicit build/commit/area preview and optional diagnostics, off by default:
  quality, viewport, input mode and rounded position only. Allowlisted bounded
  client-reported context, no automatic logs/chat/account/inventory/instance-ID
  dump. Input capped at 3200 characters to leave room under the existing 4000-rune
  stored-report limit. Server account identity and category validation unchanged.
- Labels, dialog semantics, status announcements, keyboard focus containment,
  Escape and touch-sized controls. Existing modal/backdrop/window behavior reused.
  New desktop/phone-sized routes are included in required CI interface coverage.
- Existing operator destination remains the database report queue read by
  `server/cmd/reports` (`-action list`, optionally `-status open` and `-limit`).
  Operators must use their existing authorized database configuration. No external
  forwarding, moderation action, account grants or production test report sent.
