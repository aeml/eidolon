## Delivered scope

- Administration → Player reports exposes persisted support records as expandable
  JSON, with Open/Resolved/All filters and ten-record ID-keyset pages. Reads use
  the existing database connection; every request rechecks the durable role and
  requires an audit entry. Failed audits withhold bodies; audit history does not
  copy private report text. Ordinary players and QA-only accounts have no access.
- Untrusted values render as text, not HTML. Correlated responses, bounded pages,
  disabled pending controls, cursor reset on filter changes and disconnect/access
  loss cleanup preserve the existing administration safety model. The viewer
  does not resolve reports or punish players. Phone-sized layouts wrap long JSON.
- The Mongo-only restore helper requires an exact archive and explicit data-loss
  confirmation, refuses active/ambiguous Compose API state, checks gzip integrity,
  streams bytes without shell-expanded filenames and limits restore to Eidolon.
  It never stops services automatically. External writers/concurrent deploys still
  require operator coordination; it is not a global lock or full recovery plan.
- Roadmap and operations handoff record the owner's decisions: keep open alpha
  until nearly complete, retain existing accounts/characters, invite new beta
  players, plan up to100 players and use in-game reports with admin JSON triage.
  No assertion of100 simultaneous capacity, staffing or retention policy.
- Login/source/server versions and cumulative patch notes are synchronized.
  No reward/economy/stat change, wipe, admission restriction, payment integration,
  live restore or production grant. Actor pilot/final art approval remain open.
