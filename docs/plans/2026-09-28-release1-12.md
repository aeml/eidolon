# Alpha 1.12.0 — the fourfold passage

Status: local candidate; publication and live acceptance remain pending.

## Delivered scope

- Physical Fourfold Resonance Portal at world **(28, 235)** in Lanternhold,
  east of the Dungeon Guide and south of Ilyra. Walkable stone/inlaid plaza,
  arch, four named elemental facets and shader veil. Personal claimed repair
  receipts illuminate the facets; locked/ready/active states distinguish missing
  repairs, a level requirement and available passage. OS reduced-motion preference
  suppresses animation. No actor models, downloaded textures or dynamic lights.
- Native landmark entity follows normal mouse/touch/E interaction, never Actor
  attack targeting. The modal shows requirements, lore, explicit travel, arrival
  and recall guidance. Focus is contained, Escape closes only it; departing,
  death, scene/character change and entity disposal dismiss stale interaction.
- Existing `enter_dark_realm` handler accepts proximity to the physical portal
  OR Guide, retains individual level-100/claimed-repair and legacy gates, rejects
  remote/invalid/action-blocked travel and moves only the authenticated player.
  No new protocol message, quest/reward/save schema, party bypass or paid behavior.
- Canonical `server/internal/game/content/world-locations.json` owns the three
  town Chronicle anchors. Go embeds it; the checked-in client projection is
  generated by `node scripts/generate-world-locations.mjs`, verified with
  `--check`. Server spawns and both maps consume these coordinates. Other sites
  retain their existing authoritative catalogs until their population milestones;
  this is not a claim of a complete atlas or whole-world registry conversion.
- Ilyra's final-Vigil dialogue and the Guide give plaza directions. Existing
  shared camp, its projection, recall, expedition persistence and the private
  dungeon/checkpoint/fifteen-minute rules remain unchanged.

### Candidate correction — keyboard admission

After the first push, reviewing the actual E subscription found that its
Chronicle-only search omitted the new portal. Mouse/touch and direct dialog
tests had not covered that subscription. A new regression failed for the nearby
portal while 15 existing/negative cases passed. The E search now opens the
nearby portal as a fallback after accepted Chronicle evidence, without sending
travel or granting credit. Offline/dead/distant/menu cases remain rejected.
Opening the portal also clears held movement, queued combat intent and movement
targets so the keyboard route cannot walk away underneath its modal.

Corrected scoped checks: 19 unit tests pass (1.638s), changed-file ESLint passes,
and both browser routes pass (11.8s), now pressing actual E through InputManager
and asserting no travel message until the explicit button. Artifacts:
`/tmp/eidolon-portal-1-12-20260928-keyboard/`. Earlier direct-dialog checks retain
their narrower scope; they did not establish keyboard admission.

### Hosted-browser failure and bounded-fixture correction

CI36395622961 failed only the 1440px portal route in Browser Smoke 2/3;
18/19 interface cases passed, including the phone portal case. The desktop
case exhausted 120 seconds twice, during screenshot capture and then state
polling on retry. All client/server checks and the other browser shards passed;
deployment was skipped. Failure evidence was downloaded to
`/tmp/eidolon-portal-ci-36395622961-HG7Wwl/`; the desktop capture shows the actual
portal rendered, not a missing model. This failed run is not release acceptance.

Source review found the fixture ran the entire animation gallery and unrelated
summons continuously while capturing each portal state. Replaced that fixture
with bounded calls to the production RenderSystem, actual town buildings and
colliders, portal and a Fighter reference model, following the existing crystal
presentation pattern. Kept both viewports, High/Low, all three states, keyboard
entry, held-input clearing, requirements, explicit send, focus, Escape and stale
range checks. The 120-second timeout and zero-retry local run remain unchanged.
This is presentation/input verification, not a game frame-rate benchmark; no
production rendering code or detail was reduced for this test change.

Both final routes pass in **25.3 seconds** using CI's bundled Chromium, explicitly
reporting **ANGLE Vulkan SwiftShader (Subzero)** for both viewports. Changed-file
ESLint/whitespace checks pass. Final artifacts:
`/tmp/eidolon-portal-1-12-20260928-bounded-verified/`; the preceding equivalent
bounded run passed in 25.6s and its desktop scene/phone dialog were inspected.
Hardware-gallery captures above remain separate scoped evidence, not proof of
software-renderer or future populated-world performance.
